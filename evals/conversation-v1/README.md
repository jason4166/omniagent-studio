# Conversation regression cases v1

本目录把 2026-09-21 的 HR、产品支持和销售初始真实对话探索整理为可复现的多轮用例。输入均为合成业务场景；保留原始提问顺序、新建会话边界，以及销售审批编辑、原请求重放和拒绝动作。用例不包含账号、Cookie、凭据、真实个人资料或历史会话标识。

这是**探索性质量回归材料**，不是随机抽样的准确率统计，不是新的 `EvalRun` 基准，也不是盲测或独立留出集。问题与预期在观察到初始表现后整理，可用于复现缺陷和防止回归，不能据此推断一般生产对话质量。

[用例文件](cases.json) 使用专门的多轮描述格式，**现有 Fake / `eval-real` 单轮评测框架不能直接执行此文件**。不要把它传给已有 `--dataset` 参数，也不要把人工评审结果混入冻结的 v1–v3 指标。

## 内容与复现

- `cases` 记录初始探索的逻辑链；`origin=initial_live_exploration` 表示输入来源，不代表该链已经通过。
- 每个 case 新建当前 Profile 的会话，在该 case 内依次发送 `steps`，保留真实历史。不要将上一 case 的消息偷偷注入新会话。
- `type=message` 是原始用户文本；`approval` 对当前链真实待审批项执行指定动作；`approval_replay` 完整重发它引用的首次审批请求，包括相同审批项、版本、幂等键和参数。
- 历史请求键、审批标识和 operation run ID 均不存入用例。复现时从当前服务端状态获取，普通请求使用新键，重放步骤才复用原请求。
- `expected.route` 的数组表示有明确理由的可接受分支。例如独立新会话中的“这两款”若无法消歧，可以澄清产品范围；不得编造前文。
- `targets` 将步骤关联到已观察的问题或审批控制项；`regression_recommendations` 是建议追加的验证，不能算作已执行的初始对话。

使用隔离环境和合成预置数据。产品 P-100/P-200、设备 SN-100、客户 C-100 应存在，P-999/SN-999 应不存在。按各 Profile 配置授权知识库与 HTTP/MCP 工具，并能够核对销售审批及实际写入数量。账号、地址、密钥和运行预算通过环境提供。真实模型重放仍须单独授权，本目录本身不会调用模型。

## 如何判断质量

以每步 `expected.principles` 和 `shared_expectations` 作语义评审，不要求逐字输出预设答案。结合回复、引用、路由、工具及参数、服务端原操作状态和实际副作用判定。审批提案出现时就应检查尚未写入；编辑批准后检查最终参数；重放后检查没有重复效果。

HTTP 正常、会话 `completed` 或结果 `succeeded` 只说明调用完成。答非所问、遗漏必要条件、重复无关证据、臆造剩余保修期、把申请记录当作折扣生效，仍属于质量失败。资料确实没有中秋现金金额时，明确拒答可以符合预期。

政策回答应验证引用是否来自当前授权知识库、能否定位原文，以及内容是否足以支持答案。当前实现要求完整保留所选证据单元；改善简洁性应减少重复或不相关的单元，不能删掉必要条件。工具结果追问则检查原操作及可信契约，不强行要求无关政策引用。

初始销售折扣生效追问的问题是**路由解释错误**：近期追问仍携带原批准记录。不得把此案例描述成已证实的历史丢失。拒绝后的通知追问则还涉及缺少结构化拒绝记录，必须同时验证未执行事实和效果范围。

每次重放另存实际条件及逐步评审：代码、Profile/Prompt/知识库/工具版本，模型与配置，步骤状态（通过、失败、未执行、受阻），关键证据和原因。禁止以未执行替代通过。已执行链数、消息数、审批数、质量结果与模型消耗由该次运行报告统一汇总；本目录不另存第二套运行统计，也不声称修复后已经通过真实回归。

原始输入和评审标签为合成内容，许可为 CC0-1.0。发布后需要改变输入或预期时，新建版本并说明原因，不回写冻结版本来消除失败。
