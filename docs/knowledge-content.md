# 预置知识内容

三套知识库分别维护员工制度、产品支持资料和销售政策。内容为项目原创的合成业务资料，许可见 [数据许可](data-license.md)；可用来完整演示检索、引用和业务操作，不代表任何实际公司的制度或客户记录。

| 知识库 | 覆盖内容 | 可尝试的问题 |
| --- | --- | --- |
| 员工制度 | 薪资与发薪、餐补交通和体检、工时考勤、入职转正、请假、远程办公、差旅、设备权限、培训绩效、离职交接 | 工资哪天发？公司福利怎么样？新人入职需要准备什么？忘记打卡怎么办？ |
| 产品支持资料 | 两款产品的用途与选型、桌椅日常使用、清洁维护、松动与异响排查、收货核对、退换货与保修办理 | 办公桌和椅子怎么选？椅子怎么保养？桌子晃怎么办？退货需要哪些材料？ |
| 销售政策 | 客户接洽、需求核实、跟进记录、报价准备、折扣申请、客户交接、价格异议与投诉处理 | 第一次联系客户该了解什么？跟进记录怎么写？申请优惠要准备什么？客户说价格贵怎么办？ |

一般制度问题从资料回答。具体产品、保修和客户记录通过对应工具查询；知识文档不能替代订单状态、员工个人工资单或不存在的客户记录。销售写操作仍需审批，并以执行回执确认结果。

## 更新和索引

源文件位于 [presets/knowledge](../presets/knowledge)。Markdown 标题划分内容单元，原有年假、差旅、保修、退货和折扣规则保持一致。此次通过新增文件扩展内容；重复 seed 复用相同内容，不重复建立来源或向量。

已有真实部署更新后执行：

```sh
python scripts/ops.py up --mode real
python scripts/ops.py health --mode real
```

`up` 包含构建、迁移和 seed，自动使用该部署保存的密钥引用、端口与访问设置。Fake 部署将 `real` 改为 `fake`。增加资料时应检查是否与既有制度冲突，不能靠重复上传旧文件代替内容版本管理。

## 回归验证

本次执行结果见 [访问入口与知识扩展验证](artifacts/knowledge-expansion/README.md)。

- [knowledge-v1](../evals/knowledge-v1/README.md) 保存自然中文问题、预期来源和回答要点，使用真实模型与 embedding 运行。
- `tests/test_knowledge_coverage.py` 验证 PostgreSQL 全文索引、来源定位、知识库隔离与重复 seed。它使用确定性的正文检索词，不把 Fake 随机向量测试当成语义质量证明。
- 原有 `evals/v3` 和 `evals/real-v3` 继续保留历史问题及标签。扩容后的来源排序变化和失败均应报告，不修改历史标签来获得通过结果。

在独立真实测试数据库中配置 Provider 和 embedding 后：

```sh
uv run omniagent eval-real --dataset evals/knowledge-v1/cases.json --output .pytest-tmp-knowledge-real
```

冻结问题集只能覆盖列出的场景；多轮聊天还需检查追问是否保留上下文、工具是否使用正确参数，以及用户界面是否展示清晰的引用和审批状态。
