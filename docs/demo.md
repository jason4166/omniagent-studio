# 3–5 分钟项目演示

本脚本可用于现场演示或录屏。现有 [实际截图](showcase.md) 和 [两轮验收记录](artifacts/release-public/README.md) 已可查看；仓库未提供已发布的视频链接。演示使用合成制度、产品和客户数据，业务写入发生在本地沙箱。

## 开始前

1. 按 [Quickstart](../README.md#快速启动) 启动独立部署。真实模式调用 DeepSeek 与智谱 API；无密钥时使用 Fake，并在演示中明确当前模式。
2. 打开 `http://127.0.0.1:8080`，使用 bootstrap 提示的私有初始账号文件登录。提前完成登录，不录制密码、账号文件、终端环境变量或 Provider 密钥。
3. 使用稳定数据 `P-100 / P-200`、`SN-100`、`C-100 / C-200`；重复 seed 不会改变这些标识。准备一个新会话，避免把以前的操作结果当作本轮结果。

## 操作与讲解

| 时间 | 操作 | 可直接使用的讲解要点 |
| --- | --- | --- |
| 0:00–0:25 | 打开三套 Profile 卡片，展示当前模型配置 | 这个项目面向企业知识查询和需要人工审批的操作。HR、产品支持和销售运营共用 Runtime，通过配置隔离知识库、工具和权限。 |
| 0:25–0:55 | HR 输入 `今年有多少天带薪年假？`，点击引用 | 回答附带可定位的原文引用。检索先限定知识库，输出阶段再检查引用和内容支持。 |
| 0:55–1:15 | HR 输入 `月球基地停车费是多少` | 当知识库缺少证据时拒答，不用生成的答案替代未知信息。 |
| 1:15–1:50 | 产品支持输入 `产品查询 P-100`、`保修查询 SN-100`、`MCP 产品 P-200` | HTTP 和 MCP 只读工具都进入同一个 Registry，按照权限、参数 Schema 和超时策略执行。模型不能任意选择 URL 或方法。 |
| 1:50–2:20 | 销售输入 `为客户 C-100 创建回访，备注：确认续约需求`；审批卡出现后刷新、恢复会话 | 写操作先提出工具调用并暂停。待审批任务已持久化，刷新页面后仍然可以继续处理。 |
| 2:20–2:55 | 将 `customer_id` 改为 `C-200`，修改 `note` 后批准 | 编辑参数后会重新校验权限与 Schema。审批和执行使用版本信息、稳定幂等键与下游回执处理重复请求。 |
| 2:55–3:20 | 恢复会话，查看历史，再打开管理员工具配置 | SSE 重连读取已保存的事件，风险和审批要求由服务端配置决定。页面结果可以关联到已有会话和审批记录。 |
| 3:20–3:50 | 打开架构图或验收报告中的恢复、重放结果 | 自动化验收另行验证重启、并发及响应丢失后只有一次业务效果。真实模型与离线 Fake 门禁分开；当前业务系统是本地沙箱，公开网址尚未部署。 |

演示自然语言问题时，真实 API 的网络延迟会影响时长。若需要现场展示服务重启，可在销售待审批阶段重启隔离演示部署，再恢复会话；给启动预留时间，不重启正在提供其他服务的部署。下面的脚本提供进程重启、实际 HTTP 与数据库回执的观察结果。

## 可重复验收

在已有真实隔离演示部署中执行；它会调用付费 API。两次结果写入不同目录，避免覆盖证据：

```sh
python scripts/acceptance.py --mode real --project omniagent-secure-real --output .pytest-tmp-demo-1 --demo-seconds 180
python scripts/acceptance.py --mode real --project omniagent-secure-real --output .pytest-tmp-demo-2 --demo-seconds 180
```

脚本验证重启恢复、编辑审批、重复决策、业务效果计数、HTTP/MCP 和 SSE。`--demo-seconds` 为演示安排节奏，不把等待时长当作测试断言。其他隔离部署应修改 `--project`，非默认端口同时设置 `--base-url`。脚本默认只移除本次创建的会话；`--keep-sessions` 可保留它们，不会清空审计或之前提交的业务效果。

无密钥时可改用 `--mode fake --project omniagent-secure-fake`，并在报告和演示中保留 Fake 标识。两种模式不能共用知识索引或数据库卷。

## 新文档与新 Profile

为展示系统能处理 seed 以外的内容，可在管理员上传界面导入新的合成文档并创建临时 Profile。对应的真实 API 验证脚本如下，执行前按 [开发说明](development.md) 安装锁定依赖：

```sh
uv --cache-dir .uv-cache run python scripts/live_upload_smoke.py --project omniagent-secure-real --output .pytest-tmp-upload
```

脚本验证上传去重、新 Profile、自然语言问题及原文引用，结束后仅移除自身临时数据。此步骤包含付费 chat 和 embedding 调用；已有 [新上传证明](artifacts/release-public/upload-proof.json) 可供直接复核。

## 可选：依赖查询结果的折扣审批

管理员导入 `presets/workflows/sales-preflight-v1.json`，将新 Profile 授权给演示账号。预置使用 Fake；真实部署先把 `provider_id`、`model` 和 `prompt_version_id` 三项设为与现有销售 Profile 一致（默认真实 Prompt 为 `sales:real:v1`），再验证保存。此导入不会覆盖已有 Profile。

发送“为客户 C-100 申请 10% 折扣，原因：年度续约”。系统执行一次客户只读查询和一次授权政策检索，随后显示审批。展开“前置查询与政策依据”检查回执和政策原文；可编辑原因，改变客户标识会要求重新提案。查询失败、政策版本变化或预算耗尽时不会进入写入。

此流程把依赖结果展示给审批人；审批人仍须判断申请是否符合政策，不宣称自动理解任意政策规则。
