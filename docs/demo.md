# Three-minute demonstration

Use the seeded Fake deployment at `http://127.0.0.1:8080`. All products, customers and policies are synthetic. Stable identifiers are P-100 / P-200, SN-100 and C-100 / C-200. Repeating seed keeps these identifiers stable.

| Time | Action | Visible evidence |
| --- | --- | --- |
| 0:00–0:25 | Open the workspace and its three Profile cards | One platform with three isolated configurations |
| 0:25–0:50 | HR: `年假 leave allowance`; click citation | 10-day policy and owned source locator |
| 0:50–1:10 | HR: `月球基地停车费是多少` | Clear no-evidence abstention |
| 1:10–1:40 | Support: `产品查询 P-100`, `保修查询 SN-100`, `MCP 产品 P-200` | Fixed HTTP and MCP read tools; no approval |
| 1:40–2:05 | Sales: `创建回访 C-100`; refresh and restore | Persisted pending approval, tool name and editable business arguments |
| 2:05–2:35 | Edit customer to C-200 and note; approve | Single completed write, versioned approval and traceable event |
| 2:35–3:00 | Reconnect, inspect history; open Admin tool policies | Replay does not execute; write risk and configuration validation remain visible |

For a four-minute demonstration, add an API/mock/PostgreSQL restart while the sales card is pending and then restore it. The executable script below verifies the restart, duplicate decision and effect count using actual HTTP and SQL observations; ordinary UI screenshots alone do not prove idempotency.

```sh
python scripts/acceptance.py --output .pytest-tmp-demo-1 --demo-seconds 180
python scripts/acceptance.py --output .pytest-tmp-demo-2 --demo-seconds 180
```

Both runs execute the complete scenario and write separate measured reports. Add `--project` and `--base-url` for an isolated clean deployment. The script removes only sessions it created unless `--keep-sessions` is requested. It does not erase audit or previously committed mock effects.

Screenshots can be regenerated by the [Chromium E2E instructions](development.md). Suggested stills are HR citation/refusal, pending sales approval and the administrator tool-risk view.
