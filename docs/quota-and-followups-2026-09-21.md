# 日额度结算与操作追问修复

应用源码：`d604312984c849800080048b2c2d54348a388107`。本记录区别于同日的[首次上线验收](public-launch-2026-09-21.md)，历史测试结果不转用于本次修改。

## 发现的问题

公开访客使用独立身份，但共享公开入口的日额度。排查时，该入口预留 token 已达到 497,101 / 500,000，模型调用为 56 / 200，包含此前线上验收的消耗。旧实现按保守的上下文估计永久扣量，没有在成功响应后按实际 usage 结算。

日额度拒绝又与模型服务限流共用错误类别，因此页面错误地显示“当前请求过于频繁”，重试逻辑还把本地拒绝计入了上游熔断。临时提高公开入口限额恢复了可用性，但本身并不解决上述计量和错误分类问题。

另一个问题出现在工具执行后的连续追问：会话只保存回答文字，缺少供后续引用的结构化执行凭据；前端执行详情也只依赖当前轮结果。用户继续问“然后呢”“在哪看到这个申请”时，模型容易转去检索通用政策，原操作详情随新一轮结果消失。

## 修改内容

- 每次模型调用预留持久凭据，原子更新对应的全站、用户及公开入口额度；收到有效 usage 后幂等结算日 token。调用次数及单次运行安全预算不退款。
- 消耗未知的超时、断连和崩溃仍保守保留预估额度；已确认尚未调用模型的本地拒绝结算零 token。跨 UTC 日结算仍更新原来的日桶，实际用量超额先记账再拒绝后续调用。
- 区分日额度耗尽、短时网站限流和模型服务繁忙。本地额度拒绝不触发模型重试，不污染上游熔断统计。
- 工具执行结果随会话历史保存；语义路由可以引用当前会话中的执行记录，服务端核对引用、Profile、工具和角色后展示结果，不重新执行工具。
- 每条相关回复都能展开执行记录，查看参数及返回信息。旧会话在所属用户授权检查后，可从本会话完成事件精确匹配回填记录；缺失或不匹配的事件不猜测补齐。
- 折扣申请展示客户、比例和原因；明确申请记录创建不等于折扣生效。业务含义由工具展示配置提供，没有增加真实 CRM 写入或业务审批后台。

模型仍负责判断自然语言意图；新增引用通路不代表所有问法已经验证。上下文窗口之外的记录、已过期会话及未返回的真实业务状态不能凭空恢复。
