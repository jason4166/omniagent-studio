# ADR 0015：管理只读权限与公开登录身份

状态：采用。

## 背景

作品访问者需要直接体验助手和查看后台配置，预填一个持久共享账号会同时共享聊天、审批和登录设备限制。把公开访客设为管理员又会开放配置与账号写权限。

## 决策

- 增加 reviewer 角色。配置 GET 使用独立的管理读取依赖，并根据当前有效的 Profile 授权过滤关联对象；配置写入、账号和全局运维数据继续要求 admin。
- reviewer 的业务权限映射到 member，仍受 Profile allowlist、Tool allowlist、审批、幂等、预算及 checkpoint 验证。角色本身不代表任何工具的自动批准。
- 公开登录默认关闭，部署所有者显式开启并指定 Profile 名单。浏览器只取得公开入口标识，不接触管理员密码和模型密钥。
- 每位独立访客创建带期限的数据库身份，使用现有可撤销 Cookie 和 CSRF/Origin 防护。身份、会话和缓存隔离保持不变；公开身份不能改密、提升角色或变为持久个人账号。
- 公共登录与模型调用有持久共享额度，防止重新登录重置总体消费限制。后台授权和额度在服务端执行，不依赖界面隐藏按钮。
- 关闭入口、改变公开名单、身份过期都会使公共认证失效。已有维护命令按批次清理过期身份及其会话，保留审计和幂等凭据；不自动重置正在展示的数据库。

## 后果

访客可查看配置并操作自己的业务会话；他们不能修改助手或上传资料。这里没有实现每位访客可编辑的独立管理租户。新浏览器或退出后重新登录不会拿到旧匿名身份；需要跨设备长期保存会话时，应由管理员创建个人账号。公开配置的范围由 Profile 名单及其关联资料决定。
