# ADR-0001：Prompt 信任分层与版本边界

- 状态：Accepted
- 日期：2026-08-29

## Context

OmniAgent Studio 会同时处理系统级输出约束、平台固定策略、AgentProfile
业务指令、用户输入和检索到的知识上下文。这些内容可能互相冲突，用户或
文档也可能包含试图改变系统行为的 Prompt injection。

模型的指令优先级与安全训练属于概率性约束，不能代替程序权限检查。Prompt
还需要支持确定版本引用和可重复评测，不能让相同版本 ID 在不同时间代表不同
内容，也不能让运行时数据改变版本身份。

## Decision

1. 指令冲突时依次遵循系统级输出约束、平台固定策略、AgentProfile 业务指令、
   用户当前任务和知识上下文；低优先级内容不能覆盖更高优先级规则。
2. 用户输入和检索到的知识上下文一律作为不可信数据处理。资料来源可信只表示
   内容可能可靠，不表示其中的文字获得平台指令权限。
3. AgentProfile 必须通过 `prompt_version_id` 引用确定的 Prompt 版本。管理界面
   可以提供 `latest` 查询，但运行记录、评测报告和审计证据必须保存实际版本 ID。
4. 同一个 Prompt 版本 ID 永远对应同一份模板内容。内容变化必须创建新版本；
   `content_hash` 根据固定模板计算，运行时变量值不参与版本 hash。
5. 模型生成的 RouteDecision 或工具调用只表示候选决定。真正执行工具前，程序
   必须独立验证工具白名单、参数、用户权限和审批状态，AgentProfile 不能取消
   平台固定安全策略。

## Consequences

- PromptVersion 使用确定的版本 ID 和 content hash。
- 同一个版本 ID 保存后不可覆盖，修改内容必须创建新版本。
- renderer 严格检查声明变量、模板占位符和运行时变量，并限制单个变量长度。
- renderer 只扫描原始模板一次，插入的用户或知识文本不会成为新的模板变量。
- 评测报告必须记录实际 Prompt 版本，不能只记录 `latest`。
- 工具执行仍需要独立的权限和审批检查。
- 平台策略、Prompt 模板和运行时数据需要分层组装，不能作为无边界文本拼接。

## Rejected alternatives

- 不使用 `latest` 作为可复现运行的最终版本记录。
- 不允许 AgentProfile、用户输入或知识文档覆盖平台固定策略。
- 不把 system prompt 当作工具权限的唯一安全边界。
- 不允许相同版本 ID 通过原地修改获得新的模板内容。
- 不重复解析已经插入模板的用户或知识文本。
